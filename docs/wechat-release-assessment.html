4. 不推荐的做法

不要把 piaoxiaozhu-h5（Next.js）用 web-view 塞进小程序。体验差、支付能力受限、审核风险高，且 H5 线依赖 Vercel / Neon / Stripe（海外链路）。小程序产品线以 v1 为准，H5 保留作分享落地页即可。
不要在云托管里用 PostgreSQL 容器长期存数据。云托管容器本地盘不保证持久，数据库必须外置（腾讯云数据库 PostgreSQL）。

5. 落地路线（建议顺序）

  1. 小程序先行：企业主体认证 → 确认类目与 iOS 虚拟支付合规方案 → 按最新源码重跑 build:weapp → 体验版真机验证（登录 / 上传 / OCR / 支付全链路）→ 提审。
  2. 后端并行上云：云托管建环境 → 开通 PG + Redis → api / worker 两个服务 → 配置域名、支付证书、OSS/COS → 支付真实联调（关闭 MOCK）。
  3. 收尾：接入微信内容安全接口、配置监控告警、观察一周成本后决定伸缩策略。

v1 目录已带 test_api_full.py 与 packages/core/tests（分类 / 报表 / 字段抽取），上云前建议先跑一轮全量回归，再进入支付联调。
