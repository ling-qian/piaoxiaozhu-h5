2. 顺带修掉的两个真实 bug

级别问题证据与后果
P0 配了对象存储后 OCR 全线失败 app/worker.py:41-47 原来只读容器本地盘（Path("uploads")/file_key）。一旦启用 OSS/COS，worker 本地没有这个文件 ⇒ 每张票被标记 ocr_status=failed。这是上线后必然踩到、且排查成本很高的静默失败。现已统一走 storage.download_object()，本地未命中自动回源远端。
P0 Docker 镜像根本构建不出来 旧 requirements.txt 里是裸包名 piaoxiaozhu-core，而该包只存在于仓库 packages/core、不在 PyPI；且构建上下文只有 services/api，根本拿不到它 ⇒ pip install 必报 No matching distribution found。现改为构建上下文 = v1/ 并显式 pip install ./packages/core。
P1 拆镜像后的兜底路径会 500 app/routers/files.py 的「Celery 不可用就同步跑 OCR」分支，在 api 镜像不含 paddle 时会抛 ImportError 直接 500。现已捕获并返回 503「识别服务暂时不可用」，同时把该票标记为 failed。

3. 关键设计决策（附理由）

为什么 api 可以不带 OCR 依赖

核查过导入链：paddleocr 在 PaddleOCRService.initialize() 内、cv2 在 recognize() 内才 import；app/services/ocr_service.py 只在 files.py 与 worker.py 的兜底路径里被导入——两者都是函数内导入。所以 api 镜像可以安全剥离 paddle 系依赖，镜像从 2GB+ 降到约 300MB。

存储层的选择顺序

COS_* 配了走腾讯云 COS（与云托管同厂商、可内网免流量费）→ 否则回落阿里云 OSS（原方案零改动）→ 都没配才落本地盘。生产必须配其中之一，否则容器重启后图片全丢。

迁移为什么不放在启动脚本里默认执行

多副本同时启动会并发抢 alembic 锁。手册里给了三种跑法（本地连生产库 / 云托管任务 / 临时开 RUN_MIGRATIONS=true 跑完改回），并把默认值设为 false。注意 alembic/env.py:13 会从 settings.DATABASE_URL 取库地址，所以容器内直接跑迁移不会连错库。

6. 你这边接下来要做的（按顺序）

  • 本地先跑通一次：cd v1 && docker build -f services/api/Dockerfile.api -t piaoxiaozhu-api .（验证镜像能构建）
  • 创建腾讯云 PostgreSQL 实例 + 库 + 账号；创建 Redis
  • 云托管建环境 → 建 api 服务（构建目录 v1、Dockerfile services/api/Dockerfile.api、端口 8000、健康检查 /health）
  • 填 api 环境变量 → 把 RUN_MIGRATIONS=true 部署一次跑迁移 → 改回 false
  • 建 worker 服务（规格 2 核 4GiB、不配端口）→ 填环境变量 → 部署
  • 域名：默认公网域名不能配进小程序后台，需绑定已 ICP 备案的自定义域名（或用云调用 callContainer 免域名，但撑不起图片上传）→ 再加进小程序 request/uploadFile 合法域名
  • 按手册 §6 的验证清单逐条过（含「重启 api 后图片仍可访问」以确认对象存储真的生效）
  • 回到小程序：TARO_APP_API_URL=https://<域名> npm run build:weapp → 上传体验版
顺序上有个依赖：小程序体验版要联网，必须先有公网 HTTPS 后端。所以「部署后端」是拿测试流量的第一块多米诺骨牌。
