## 采购清单与成本（用户问：还要自己买云服务吗）

**结论：要。云托管之外必须另买 4 样**（详见 `v1/infra/cloud-hosting.md` §12）：
腾讯云 PostgreSQL（同地域才能内网）、Redis（**云托管官方明确不支持部署数据库/Redis 等有状态服务**，所以不能在云托管里起 Redis 容器）、
对象存储（票据图片，约 1–5 元/月，零头）、域名+备案（仅走公网才需要）。

**两个关键发现（都已联网核实，2026-10）**
1. **云托管自己不提供域名备案功能**。官方原文：「微信云托管主要面向小程序/公众号业务，一般情况下无需使用自定义域名，
   因此暂未支持域名备案功能。当前推荐**另外购买服务器专门做备案之用（买最便宜的即可）**」。
   ⇒ 想要域名 = 域名费 + 另买一台最便宜服务器拿备案服务号，这笔极易漏。
   但同文档开头也明确：小程序/公众号走 CallContainer 调用云托管服务**不需要域名、不需要备案**。
2. **「首个环境 3 个月免费额度」实际只够约 12 天**。赠送 CPU 720 核时 / 内存 1440 GB时，
   而我们 api(0.5核1G)+worker(2核4G) 常驻每天就烧 CPU 60 核时 / 内存 120 GB时 → 720/60 = 1440/120 = 12 天。
   预算要按「约两周后开始计费」做，别按三个月。

**官方定价（2026-10 核对）**：CPU 0.055 元/(核·时)、内存 0.032 元/(GB·时)、构建 0.05 元/分钟、公网流量 0.8 元/GB；
免费额度 CPU 720 核时 / 内存 1440 GB时 / 构建 600 分钟 / 公网 5GB。**走 CallContainer 不计公网流量**（走微信私有协议）。

**月成本三档（均不含 PG/Redis）**
- A 双服务常驻：api 0.5核1G ≈43.5 + worker 2核4G ≈173.7 ≈ **217 元/月**（加 PG/Redis 后约 310–450 元/月）
- B **内测推荐**：worker 最小副本设 0，按需启动 ≈ **58 元/月**（代价：首张票等冷启动）
- C 砍掉 worker+Redis，api 改用 `Dockerfile.worker` 同步跑 OCR（代码已有兜底路径）≈ **174 元/月**，省 Redis 费
⇒ 内测期用 B；真实用量出来再决定是否常驻。

## ⚠️ 重要更正：worker 最小副本绝不能设 0（上轮的「方案 B」已撤回）

用户问「我们的项目现在不能用云托管吗」→ 核实官方《开发常识》扩缩容一节后发现上轮建议有硬伤：

**官方原文**：「自动扩缩容只根据 **HTTP 请求流量**判断，如果服务**不接受外部请求**，只是在自行跑任务，
**会被「误判」为没有使用，触发缩容**。此种场景，请手动设定实例副本数最小值为 1，保持常驻。」

我们的 worker 正是「不接 HTTP、只跑 Celery」的服务，完全命中：
- 最小副本 0 → 半小时无流量缩容到 0；而**扩容同样由 HTTP 流量触发** ⇒ 可能永远拉不起来
- 后果不是「首张票慢」，而是 **OCR 任务全堆积在 Redis 里无人处理**（静默故障，很难排查）
- FAQ 也确认常驻方法：服务管理 → 服务设置 → 基础信息 → 最小实例副本数设 1

⇒ **worker 常驻是硬要求 ≈174 元/月**；想省只有一条路：砍掉 worker 让 api 同步跑 OCR（代码已有兜底路径，api 改用 `Dockerfile.worker`）。
已改手册 §2.1/§2.2/§7/§12.4 并加更正说明。

**其他本轮核实的官方事实**
- PG/Redis 采购硬要求：**与云托管环境在同一 VPC**（官方 FAQ：「买在和云托管同一个 VPC 下即可」；VPC 路径：控制台→设置→环境设置→网络）。
- FAQ Q8：目前仅支持一个监听端口，「一个服务只建议包含一个进程」⇒ 正好支持我们 api/worker 拆两服务的做法。
- 「我们的项目现在不能用云托管吗」的答案：**能用，项目侧已就绪**（Dockerfile 拆分、PORT 自适应、/health、迁移链实测、0.39MiB 代码包、存储抽象、启动体检、preflight）；

## 本地联调 ERR_CONNECTION_REFUSED 的诊断与修复（用户贴了 devtools 报错）

**报错形态**：`GET/POST http://192.168.10.101:8000/api/... net::ERR_CONNECTION_REFUSED`

**4 步证据法定位（本此实测，一次命中）**：
1. `grep TARO_APP_API_URL apps/miniapp/.env` → 当前配置值
2. `ipconfig getifaddr en0` → 本机当前局域网 IP
3. `grep -ohE "http://[0-9.]+:[0-9]+" apps/miniapp/dist/*.js dist/pages/*/*.js | sort | uniq -c` → **产物里实际编译进去的地址**
4. `lsof -nP -iTCP:8000` → 有没有进程监听

**本次结论**：`.env`、当前 IP、dist 产物三者都是 `192.168.10.101:8000` 完全一致 ⇒ 地址没错，
**纯粹是后端没启动**（lsof 为空）。

**启动命令（已验证可跑通）**：
```bash
cd v1/services/api
./venv2/bin/python -m uvicorn app.main:app --host 0.0.0.0 --port 8000
```
**实测结果**：`/health` 本机与走局域网 IP 均 200；登录链路通——用假 code 调
`POST /api/auth/wechat/login` 返回微信 `errcode=40029 invalid code`，
**证明 WX_APPID/WX_SECRET 已正确生效**（换成 devtools 里的真 code 即可登录成功）；
受保护接口正确返回 401。启动日志里的两条告警是预期：未配对象存储（本地开发可接受）、微信支付未配置（支付已关）。
`.env` 中 `PAYMENT_MOCK_ENABLED=false`、`ALLOW_DEV_LOGIN` 未设置（默认 false）——**这两项状态是安全的**。

**必须记住的机制**：`TARO_APP_API_URL` 是**编译期常量**（`config/index.ts` 的 `defineConstants`），
所以「换 Wi-Fi / 换网络 ⇒ 改 .env ⇒ **必须重新 `npm run build:weapp`**」，热重载不会重新编译它。
`config/index.ts` 的「非 HTTPS 告警」只在 `NODE_ENV=production` 触发，本地 HTTP 联调不报警（预期行为）。
**其他常见原因**（本次已排除，备查）：后端只 bind 了 127.0.0.1、手机与 Mac 不同 Wi-Fi、
macOS 防火墙拦截入站、devtools 未勾选「不校验合法域名」。

## 两条 devtools 报错的定性（用户继续贴日志）

**① `[wxapplib]] backgroundfetch privacy fail {errno:101, private_getBackgroundFetchData:fail:jsapi invalid request data}`**
- **不是我们的代码**：全仓 grep `getBackgroundFetchData|backgroundfetch` 在 `src/`、`config/` 下 **0 命中**。
- 是**微信基础库自身**发的（`[wxapplib]]` 前缀 + `private_` 前缀 = 走了客户端隐私模块的探测链路）。
  `wx.getBackgroundFetchData`（周期性更新）是微信早已废弃的私有接口，新基础库在隐私探测时会顺手探这些废弃接口然后失败刷日志。
- **不影响功能，可忽略**。判据：我们自己的接口（登录/上传/OCR）是否正常。
- 何时要管：只有当 `chooseImage` / `chooseAvatar` 等**我们真正用到**的接口开始报 privacy fail，才说明 mp 后台
  「用户隐私保护指引」与代码不同步——那是提审前必配项（手册 §6）。

**② `chooseImage:fail cancel`（MiniProgramError）**
- **是我们的问题**：`upload/index.tsx` 两个 `chooseImage`（相机/相册）都没写 `fail` 回调，
  用户点「取消」→ 微信走全局 fail → Taro 抛未处理 Promise → 控制台红字。
- 已修：新增 `onChooseImageCancelSafe(err)`，`errMsg` 含 `cancel` 时静默返回，其余失败才 toast；两处调用都挂上。
- 验证：`tsc --noEmit` 在 `src/` 下 0 错误；另核查 `requestPayment` 的 cancel 早已处理（member/index.tsx），
  `chooseAvatar` 是 Button openType 组件级不会抛；无 showActionSheet/chooseLocation/scanCode 等其他取消敏感 API。
- **改源码后必须重新 `npm run build:weapp`**（或 watch 自动重编）才能在 devtools 生效。

## 换网络后 ERR_CONNECTION_TIMED_OUT（第 3 次因换网改 IP）

**错误演进**：`ERR_CONNECTION_REFUSED`（后端没起）→ `ERR_CONNECTION_TIMED_OUT`（换网络后）。
**两者区别很重要**：
- REFUSED = IP 可达但没人监听（或 IP 是别的机器的）
- **TIMED_OUT = IP 根本不可达/被丢包** ⇒ 九成是「Mac 换网后 IP 变了，包里还是旧 IP」

**决定性证据技巧**：`lsof -nP -iTCP:8000` 能看到微信客户端的连接状态——
`wechatweb ... TCP <当前Mac IP>:51525 -> 192.168.10.101:8000 (SYN_SENT)` 说明手机还在连旧 IP 且等不到任何回应。
比单看报错信息准确得多，以后作为首选诊断手段。

**本次实测**：Mac IP 已从 192.168.10.101 变成 **172.16.20.37**（en0，默认路由出口）；
后端进程仍在跑（PID 56110，`*:8000`），`curl http://172.16.20.37:8000/health` → 200 OK。
**这是第 3 次因换网改 `.env`**（172.16.20.37 → 192.168.10.101 → 172.16.20.37）。
已把 `apps/miniapp/.env` 更新为当前 IP 并在注释里记了两条根治建议：
① 路由器上给 Mac 做 DHCP 保留（固定 IP）；② 试 `<Mac名>.local:8000`（mDNS，IP 变也不用改，
但部分安卓/路由器不解析 .local）。**仍需用户本机 `npm run build:weapp` + devtools 点「编译」**——
本沙箱跑不了 Taro 构建（`mkdir dist` 被 brokered-fs 拦，见上）。
