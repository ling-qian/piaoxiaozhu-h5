先看 3 个坑

这三条踩了会浪费几小时
1. 支付证书不能用本机路径
你现在 .env 里是 /Users/tom/cert/.../apiclient_key.pem —— 容器里没有这个文件，启动体检会直接失败。 必须把 PEM 全文贴进环境变量（代码已支持：值里含 -----BEGIN 就按内容解析）。
2. Neon 从本机访问很慢（1–7 秒），但部署后不一定
本机（家庭宽带）→ 新加坡实测 1.1–7.5 秒/接口，抖动极大。云托管在广州机房，跨境出口通常好很多， 但不保证。部署后第一件事就是测延迟（见 ⑥），不行就把 DATABASE_URL 换成腾讯云 PG （一行改动，代码零修改）。
3. worker 的最小副本不能设 0
设 0 时没有实例消费 OCR 队列：上传票据后永远停在「识别中」，且不会报错。 内测若不想开 worker，需要把 OCR 改成同步（当前默认异步）。

⑥ 延迟验证（Neon 的关键一步）

部署后第一件事，决定 Neon 能不能用
# 连测 5 次，看中位数
for i in 1 2 3 4 5; do
  curl -o /dev/null -s -w "%{time_total}\n" \
    -H "Authorization: Bearer <token>" \
    https://<你的域名>/api/me
done
结果判断动作
< 300 ms✅ 可用继续往下走
300–800 ms⚠️ 勉强先用着，观察
> 800 ms❌ 体验差换腾讯云 PG（见下）

换成腾讯云 PG（一行改动）

# 只需改云托管环境变量这一个值，代码零改动、不用重新打包
DATABASE_URL=postgresql+asyncpg://piaoxiaozhu:<密码>@10.x.x.x:5432/piaoxiaozhu

前提是买了腾讯云 PostgreSQL 且与云托管同 VPC。数据迁移：pg_dump Neon → psql 腾讯云，量很小。
