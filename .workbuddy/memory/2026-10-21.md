### 部署失败原因：greenlet 缺失（已修）

**症状**：容器日志刷屏 `ModuleNotFoundError: No module named 'greenlet'`，服务反复重启，
外部访问返回 `SERVICE_VERSION_NOT_FOUND`。

**根因**：SQLAlchemy 的 asyncio 扩展依赖 greenlet。**SQLAlchemy 的 macOS wheel 自带
greenlet，Linux wheel 不带**——所以本地 venv 从来不报，Linux 容器必挂。
requirements-api.txt / requirements.txt 都没显式声明它。

**修复**：两个 requirements 都加 `greenlet>=3.0`（附注释说明 macOS/Linux wheel 差异）。

**依赖清单全量核对**（防止同类问题第三次发生）：
app/ 的第三方 import 只有 celery / cryptography / fastapi / httpx / jose /
piaoxiaozhu_core / pydantic / pydantic_settings / sqlalchemy，逐个确认都有提供者。
其中 `cryptography` 由 `python-jose[cryptography]` extra 提供（wechat_pay.py 直接 import 它）。

**重新打包**：`/tmp/v1-codebundle.zip` 197K / 117 文件，greenlet 已在内，

### 第二次部署失败：DATABASE_URL 环境变量没配（已修 + 已给清单）

**症状**：容器刷屏 `ModuleNotFoundError: No module named 'aiosqlite'`，
traceback 里出现 `sqlalchemy/dialects/sqlite/aiosqlite.py` ⇒ 引擎在用 **sqlite** 方言。

**根因**：`config.py` 的 `DATABASE_URL` 默认值是 sqlite（本地开发兜底）。
云托管环境变量里**没配 DATABASE_URL** ⇒ 回落 sqlite ⇒ 镜像没装 aiosqlite ⇒ 崩。

**为什么体检没拦住**：`_check_runtime_config()` 里**已经有** sqlite 检查且生产会拒绝启动，
但它跑在 `@app.on_event("startup")`；而 `app/models/database.py` 在 **import 阶段**就
`create_async_engine`（比 startup 更早）⇒ 先崩在 import，体检根本执行不到。
**教训：import 期就执行的代码，配置校验必须放在配置加载时。**

**修复**：`config.py` 加 `model_post_init`：`APP_ENV=production` 且 URL 是 sqlite
→ 直接抛带操作指引的 ValueError。实测三种场景：prod+sqlite 拒、prod+Neon 过、
dev+sqlite 仍可用。

**交付物**：

  （DATABASE_URL 已去掉 sslmode；WX_NOTIFY_URL 已填成云托管域名）
- 新部署包 `/Users/tom/Desktop/v1-codebundle.zip`（198K / 117 文件，安全复查 0 命中）

### 生产登录 500 → 已加固（待重新部署）

**现象**：真机/模拟器调 `/api/points` 报 401（Unauthorized）。
根因是**登录没成功**：直接 POST `/api/auth/wechat/login` 返回 **500**（本地同样调用返回干净 400）。

**根因分析**：`_wechat_code2session()` 里 httpx 调 api.weixin.qq.com 这一步**没有任何异常保护**——
网络失败/代理/非 JSON 都会变成 500，前端只看到"登录失败"，无任何线索。
且 httpx 默认 `trust_env=True` 会读取容器注入的代理环境变量，云托管里很可能因此连不出去。

**已加固**（本地回归 15/15、假 code 返回干净 400）：
- `trust_env=False`（绕过容器代理）
- httpx.HTTPError → 502「微信登录服务网络不通」
- 非 JSON → 502 + 日志
- 缺 openid → 502 + 日志
- 三处都写 `logger.error`，部署后可在云托管日志看到真实原因

**新包**：`/Users/tom/Desktop/v1-codebundle.zip`（198K / 117 文件，安全复查 0 命中）

**诊断捷径**：重新部署前，可先在云托管「日志」里搜 `jscode2session` 或 `Traceback`，
看当前 500 的真实原因——若是环境变量问题，改控制台即可，不必重新部署。
